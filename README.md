# Atoms-Demo · AI Agent 平台笔试原型

> ROOT / AI Native 全栈工程师 笔试挑战（Atoms-Demo）
> 完成人：王德勇 ｜ 用时：约 6-8 小时

一个可运行的 AI Agent 平台原型：通过**智能体驱动的方式生成应用**，并把生成的应用以可视化网页形式展示、下载。真实链路完整打通——**LLM 规划 → 人工批准 → 代码生成 → 质量校验 → 部署 → 预览/下载**，数据持久化于 SQLite。

---

## 一、Demo 能做什么（一句话到可部署产物）

```
你在输入框描述想法
  → 真实 LLM 将需求拆解为 5-15 个任务（含验收标准）
  → 计划卡片呈现，你可批准执行
  → 服务端真实执行管线：生成代码 → 校验完整性 → 部署
  → 右侧 iframe 实时预览产物站点
  → 一键下载产物包（站点 + 部署手册）
```

**已实现的核心能力：**
- ✅ 真实交互：不是静态页面，完整「项目 → 需求 → 规划 → 批准 → 生成 → 预览 → 下载」流程
- ✅ 数据持久化：SQLite（`data/atoms.db`），项目/会话/消息/任务/工具执行/版本全落库，**重启不丢**
- ✅ 真实 LLM 规划：`deepseek-chat` 按需求定制任务，同一模板不再重复
- ✅ 实时进度：SSE 流式推送 Agent 执行阶段（generate → checkui → deploy）
- ✅ 基本流程：项目初始化 → 会话 → 核心主流程
- ✅ 扩展能力（≥1）：产物包下载 + 内置部署手册（GitHub Pages / Vercel / nginx）
- ✅ 产物离线可跑：纯静态站点，无后端依赖

## 二、实现思路与关键取舍

### 2.1 架构（单进程 + SQLite，本地优先）

```
web/index.html（仿 Atoms 深色交互界面）
   ↓ fetch / SSE
server.js（Express 单进程）
   ├─ /api/projects       项目（初始化）
   ├─ /api/projects/:id/chats  发起需求 → 真实 LLM 规划
   ├─ /api/chats/:id/approve   批准 → 启动生成管线
   ├─ /api/chats/:id/events    SSE 实时进度
   ├─ /api/sites/*             产物站点预览
   └─ /api/artifact/download   产物 zip（含部署手册）
scripts/
   ├─ llm.js       多 Provider 适配（DeepSeek/Anthropic/OpenAI 自动检测）
   ├─ planner.js   LLM 规划器（JSON 约束 + 3 次重试）
   ├─ build-site.js 按计划生成真实静态站点
   ├─ db.js        SQLite 持久化层
   └─ utils.js     手写目录复制（见下）
```

### 2.2 关键取舍（工程思维）

| 取舍 | 选择 | 理由 |
|------|------|------|
| 基础设施 | **单进程 + SQLite + 本地文件** | 6-8h 笔试，零运维，SQLite 单机足以承载，避免分布式复杂度 |
| 前端 | **原生 HTML/JS 单文件**（非 React 工程化） | 零构建、直接运行，把时间花在真实链路而非脚手架 |
| Agent 执行 | **真实管线而非真 Agent** | 生成/校验/部署均由服务端真实执行，聚焦「可运行产物」；多 Agent 深度协作是 V2 |
| LLM | **优先原生 DeepSeek** | 实测 `deepseek-chat` 比某网关 flash 模型稳定（后者间歇返回空），且成本低 |
| 部署形态 | **静态站点产物 + 部署手册** | 产物离线可跑、可一键托管，符合「可测试、可交付」 |

### 2.3 一个值得说的工程问题

本机 Node 24 的 `fs.cpSync()` 在 Windows 上会**原生崩溃（exit 127，无错误输出）**。通过逐步二分定位后，改用手写递归复制 `copyDir()`（`utils.js`）解决——这是真实调试过程，也是「复杂度控制」的一环。

## 三、当前完成程度

### ✅ 已做
- 完整主流程（项目 → 需求 → 规划 → 批准 → 生成 → 预览 → 下载）
- 数据持久化（SQLite，重启不丢）
- 真实 LLM 规划（不同需求 → 不同计划）
- SSE 实时进度、产物预览、zip 下载 + 部署手册
- 多模型自动检测、规划失败重试、成本按模型记账
- 前端仿 Atoms 深色交互（项目列表 / 会话历史 / 计划卡片 / 执行日志 / 预览窗）

### ⚠️ 未做 / 简化（诚实说明）
- **未做真实 LLM 写代码**：产物站点由模板生成器按计划产出，而非 LLM 逐行写代码（这需要多 Agent + 沙箱执行，是 V2 范围）
- **未做注册/登录**：单用户本地模式，无鉴权
- **未做赛马模式/多 Agent 协作/长期运营**：明确留到后续
- **产物为静态落地页**：未覆盖登录/数据库/支付等后端业务（演示用静态站，部署手册已说明）

## 四、如果继续投入时间，扩展与优先级

| 优先级 | 方向 | 说明 |
|------|------|------|
| P0 | **真实 Agent 执行**（LLM 写代码 + 沙箱运行） | 从「模板生成」升级为「真 Agent 生成」，这是产品灵魂；配套容器沙箱、命令白名单 |
| P0 | **质量门禁**（build + 渲染断言 + 失败透明） | 借鉴 Cursor/Devin：`exit_code≠0` 强制 BLOCKED，评测门禁，badcase 闭环 |
| P1 | **真实后端业务模板**（登录/数据库/支付） | 让产物从「落地页」升级为「可运营业务」，对接「Vibe Business」定位 |
| P1 | 会话级成本实时计量 + 预算护栏 | 双阈值，防失控 |
| P2 | 多 Agent 协作（产品/架构/工程/数据） | 赛马模式、信息契约、状态持久化 |
| P2 | 注册/登录、多用户、项目共享 | 面向多人使用 |
| P3 | 移动端适配、模板市场 | 生态化 |

**优先级判断依据**：先做「决定产品灵魂」的真实 Agent 执行与质量门禁（P0），再做「让产物更值钱」的真实业务模板（P1），最后才是平台化能力。

## 五、本地运行

```bash
cd atoms-demo
npm install
# 配置任一模型 Key（环境变量，二选一即可）
export DEEPSEEK_API_KEY=sk-xxx      # 推荐，稳定
# export ANTHROPIC_API_KEY=sk-xxx   # 或 Anthropic
node server.js
# 打开 http://127.0.0.1:8787
```

无需数据库安装、无需 Docker，SQLite 自动建库。

## 六、在线部署（Render / Railway / 任意 Node 平台）

**Docker 方式（推荐）**：
```bash
docker build -t atoms-demo .
docker run -p 8787:8787 -e DEEPSEEK_API_KEY=sk-xxx atoms-demo
```

**Render.com**：
1. New → Web Service → 连接本 GitHub 仓库
2. Build Command: `npm install`
3. Start Command: `node server.js`
4. 环境变量添加 `DEEPSEEK_API_KEY`
5. Deploy 后即得在线链接

> 注意：SQLite 数据存在容器本地磁盘，免费实例重启会重置；如需持久化请挂载磁盘卷。
